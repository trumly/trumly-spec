# Contributing

trumly-spec is open source under the Apache License 2.0, and it is developed by Catchlove Ltd.

## Issues and discussions

Problems with the specification, and proposed changes to it, are welcome as issues: please use the forms. Questions and ideas that are not yet a proposal belong in Discussions. Please include the smallest model or file that shows the problem.

The maintainers decide what goes into the specification. A proposal is considered, not voted on, and a change to the file format or the rule language needs a conformance case.

Feedback on the trumly cloud editor is not handled here. Use the feedback link in the app, or write to hello@trumly.co.

## Pull requests

We are not accepting pull requests yet, and publishing your own packs is not open either. How both will work is not decided: see [what is not decided yet](https://spec.trumly.co/about#not-decided). When they open:

- every contribution is reviewed by a maintainer before it is merged, and nothing is merged without that review;
- a contributor licence agreement must be signed before a first contribution can be merged. The agreement is not ready, which is why pull requests are not open;
- contributions are licensed under the Apache License 2.0, as section 5 of that licence provides.

Changes to the file format or the rule language also need a fixture in the conformance suite that shows the new behaviour.

## Security

Please do not report a security problem in a public issue. Use GitHub's private vulnerability reporting on this repository, as described in SECURITY.md.
